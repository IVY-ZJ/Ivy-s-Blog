指南

写博客、推链接、传图片的完整教程

IVY ·2026 年 8 月 9 日·10 分钟

这篇教程写给未来的自己，也写给任何想在这套博客上发内容的同学。全部是纯静态操作：复制一个文件 → 粘贴内容 → 登记元数据 → git 推送。看完你就会发文章、加链接、传图片和音频了。

你需要的东西 一个 Git 客户端（或命令行），和一个能编辑 HTML 的文本编辑器（VS Code / Sublime / 记事本都行）。

一、怎么发一篇新文章

这套博客里，一篇文章 = 一个 HTML 文件 + 一行元数据。

第 1 步：复制模板

打开 posts/ 文件夹，把任意一篇文章（推荐 why-i-write.html）复制一份，重命名为你的文章名，例如：

posts/我的第一篇笔记.html

也可以直接用英文短横线命名，更稳（避免中文文件名在某些服务器上出问题）：

posts/my-first-note.html

第 2 步：改标题和头部信息

在文件顶部，把 <title>、<meta name="description"> 改成你的标题和一句话简介。

在正文区的 .article-head 里，修改：

<h1>文章标题</h1>
<div class="article-meta">
  <span>2026 年 8 月 9 日</span>
  <span>·</span><span>8 分钟</span>
</div>

第 3 步：写正文

所有正文放在 <div class="prose"> ... </div> 里面，用最普通的 HTML 写就行：

<p>段落文字……</p>
<h2>二级标题</h2>
<h3>三级标题</h3>
<ul><li>列表项 1</li><li>列表项 2</li></ul>
<blockquote>引用别人的话</blockquote>
<strong>加粗</strong> 和 <code>行内代码</code>

第 4 步：登记元数据

打开 assets/js/posts-data.js，在数组里加一条（注意是英文逗号分隔，前一条末尾要有逗号）：

{
  slug: "my-first-note",        // 和文件名一致（不含 .html）
  title: "文章标题",
  cat: "笔记",                  // 笔记 / 资料 / 随笔 / 指南
  date: "2026-08-09",          // 格式 YYYY-MM-DD
  readTime: "8 分钟",
  excerpt: "一句话摘要，会显示在卡片上。",
}

保存后，首页「最新文章」和「全部文章」页面会自动出现这篇，不用改别的文件。

二、怎么加链接

普通链接写在正文里，用 <a> 标签：

这是 <a href="https://github.com/IVY-ZJ" target="_blank" rel="noopener">我的 GitHub</a>。

target="_blank" 表示在新标签页打开，rel="noopener" 是安全写法，建议每次都带上。

资源卡片（网盘 / 下载链接）

如果想在「资源分享」页面放一个醒目的下载按钮，打开 resources.html，复制下面这段再改：

<div class="resource reveal">
  <div class="res-icon" style="background:linear-gradient(145deg,#007AFF,#5856D6)">
    <svg viewBox="0 0 24 24" width="22" height="22" fill="none" stroke="currentColor" stroke-width="1.8"><path d="M4 5h16v14H4z"/><path d="M8 9h8M8 13h6"/></svg>
  </div>
  <div class="res-body">
    <div class="res-title">资料名称</div>
    <div class="res-desc">一句话说明</div>
    <span class="res-code">提取码：xxxx</span>
  </div>
  <a class="btn btn-ios res-action" href="https://pan.baidu.com" target="_blank" rel="noopener">前往网盘</a>
</div>

三、怎么传图片

第一步，把图片放进 assets/img/ 文件夹（或者新建一个 posts/images/ 目录）。第二步，在正文里用 <img> 引用它：

<img src="../assets/img/你的图片.png" alt="图片说明" />

小提示：

  • 路径里的 ../ 是因为文章在 posts/ 子目录里，要先「往上跳一层」才能到 assets/。
  • 图片建议先压缩到 200KB 以内（可用 TinyPNG），否则网页会变慢。
  • 尽量用英文文件名，比如 circuit-diagram.png。

想让文章顶部带一张横幅图？直接把图片放进 assets/img/，然后在正文里用 <figure> 包裹并附说明文字，或者用 <img> 内联；不需要任何特殊的封面条占位。

四、怎么放音频 / 视频

直接把音频文件放进 assets/audio/（新建），然后在正文里写：

<audio controls preload="metadata">
  <source src="../assets/audio/你的音频.mp3" type="audio/mpeg" />
  你的浏览器不支持音频播放。
</audio>

视频同理（把 assets/video/ 目录建好）：

<video controls preload="metadata">
  <source src="../assets/video/你的视频.mp4" type="video/mp4" />
  你的浏览器不支持视频播放。
</video>

需要图文并茂的「媒体块」样式（带标题的音频/图片卡片），可以复制下面这种写法：

<div class="media">
  <div class="media-block">
    <div class="media-cap">音频标题</div>
    <audio controls preload="metadata">
      <source src="../assets/audio/xxx.mp3" type="audio/mpeg" />
    </audio>
    <p class="media-desc">这段音频讲了什么……</p>
  </div>
</div>

五、怎么分享大文件

GitHub 对单个文件有 100MB 硬限制（超过 50MB 还会警告），所以大文件一律走网盘：上传到百度网盘 / 阿里云盘，把链接贴进文章（见上文「加链接」部分），再把提取码写在旁边。本站的「资源分享」页面就是这样做的。

小文件（< 50MB）可以直接放仓库里下载，用文件行样式：

<div class="file-row">
  <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.8"><path d="M14 3v5h5"/><path d="M6 3h9l4 4v14H6z"/></svg>
  <span class="file-name">大二物理笔记.pdf</span>
  <span class="file-size">12 MB</span>
  <a class="file-link" href="../assets/files/物理笔记.pdf" download>下载</a>
</div>

把文件放到 assets/files/，href 指向它即可。download 属性让浏览器直接下载而不是打开。

六、怎么推到 GitHub（发布上线）

本地改完，打开终端，在博客文件夹里依次执行：

cd 你的博客文件夹
git add -A
git commit -m "写点东西"
git push

如果这是第一次配置仓库（只做一次）：

git init
git add -A
git commit -m "init"
git branch -M main
git remote add origin https://github.com/IVY-ZJ/Ivy-s-Blog.git
git push -u origin main

推送后，GitHub Pages 会自动重新构建，等一两分钟，访问：

https://ivy-zj.github.io/Ivy-s-Blog/

想直接在线编辑？也可以打开仓库网页，找到 posts/ 下的文章点「编辑」图标，改完点 Commit changes —— 更简单，但记得每篇文章都要同步改一下 assets/js/posts-data.js 里的登记信息。

最后一句 写完先 python -m http.server 8000 在本地预览一遍，再推上去，就不会出现「线上打不开」的尴尬了。

七、发布前更新「关于我」统计数字（必做）

「关于我」页的文章数和资源数不能靠手改，每次发了新文章或加了新资源，都要让它跟实际一致。本站用一个脚本自动同步：

node scripts/update-stats.js

它的计数口径（也是本站规范）：

  • 文章数 = assets/js/posts-data.js 里 POSTS 数组的条目数（全站文章/资料的单一信源，每发一篇都要在这里登记）。
  • 资源数 = resources.html 里 class="resource reveal" 的卡片数量（即「资源分享」页的网盘合集条目）。

脚本会把算出的数字回填进 about.html（锚点注释 <!--STAT-POSTS--> 和 <!--STAT-RESOURCES--> 之间），不要手动改这两个数字。每次 git commit 之前跑一次即可，幂等、可重复执行。

发布清单 发文章 / 加资源后，按顺序：① 登记 posts-data.js（含 tags）或加 resources.html 卡片 → ② node scripts/update-stats.js 同步统计 → ③ 本地预览 → ④ git add -A && git commit && git push。

第 3 步：同步标签到右侧面板与标签页

首页右侧「标签」面板和 tags.html 标签页都不是静态写死的，它们由 assets/js/app.js 在页面打开时，自动从 posts-data.js 的 tags 字段聚合生成。因此，只要新文章的 tags 登记进了 posts-data.js，刷新首页后它们就会出现在右侧面板（数量过多时面板内部可滚动）。

注意：如果刷新后没看到新标签，大概率是浏览器缓存了旧版 app.js 或 posts-data.js，按 Ctrl + Shift + R 强制刷新即可。

八、受保护 PDF 的混淆与嵌入规范（必读）

「课程资料」里需要受保护的 PDF（如工程训练复习课、食品安全笔记）不能原样上传——否则谁都能从 GitHub Pages 直接下载。本站用一套前端混淆 + 运行时解密：源 PDF 先被 scripts/obfuscate_pdf.py 打乱成 .dat，页面加载时由 assets/js/fss-viewer.js 在内存里还原成 blob 再渲染。这叫混淆不是加密（密钥随页面下发），目的只是挡住爬虫和随手下载。

第 1 步：把 PDF 混淆成 .dat

把源 PDF 命名为 assets/files/<页面名>.src.pdf（例如 engtrain-review.src.pdf），然后：

python scripts/obfuscate_pdf.py \
  --src assets/files/engtrain-review.src.pdf \
  --dst assets/files/engtrain-review.dat
  • 不传参数时默认处理 fss-notes，兼容旧用法。
  • 输出的 .dat 必须与页面同名（engtrain-review.html ↔ engtrain-review.dat）。
  • 源 PDF（.src.pdf）不要提交到仓库，本地留底即可；只上传 .dat。

第 2 步：在课程页嵌入

课程页写 <body data-fss="pdf">，正文放一个容器即可，多数情况无需任何属性：

<section class="fss-pdf-box fss-pdf-full" data-fss-pdf></section>

fss-pdf-full 必须带上：它让 PDF 嵌入框高度等于 100dvh - 11px，上边界对齐导航栏下沿，下边界几乎贴合视口底部。11px = 导航栏 top 间距 6px + 栏高 54px + 栏内上下 padding 各 8px - 65px。

脚本会按当前页面文件名自动找 ../assets/files/<页面名>.dat。需要自定义时，用属性覆盖：

<section class="fss-pdf-box fss-pdf-full" data-fss-pdf
         data-dat="../assets/files/engtrain-review.dat"
         data-title="工程训练复习课 PDF 预览"
         data-size="约 4.4 MB"></section>
四条铁律 ① 容器必须带 fss-pdf-full，否则 PDF 框只有 72vh，上下会空出大片留白；② 混淆脚本里的 KEY 必须和 fss-viewer.js 里的 KEY 一字不差，否则前端报「解密校验失败」；③ 必须用本地服务器（python -m http.server）打开，file:// 协议下浏览器禁止读取静态文件，PDF 一定加载不出来；④ 改完记得跑 node scripts/update-stats.js（见第七节）再提交。

九、怎么新建一个课程专区

每门课都要有一个专区落地页（如 course-food-safety.html、course-engtrain.html、course-ode.html），里面用卡片列出该课的所有资料，每张卡片点进去是独立的阅读页。以「常微分方程」为例，完整流程如下。

第 1 步：放资料源文件

纯文本 / Markdown 笔记直接放进 assets/files/：

assets/files/ode-notes.md   ← 常微分方程学习笔记（单一信源，也是下载入口）

阅读页用 data-fss="qa" 拉取这个 .md 并在前端渲染，公式用 KaTeX、!!! note "标题" 提示框、Markdown 表格都会自动识别，无需手写 HTML。

第 2 步：建阅读页

复制 course/engtrain-notes.html（或 course/fss-qa.html）改三处：

<body data-fss="qa">
  …
  <a class="article-cat" href="../course-ode.html">课程资料</a>
  <h1>常微分方程学习笔记</h1>
  …
  <a href="../assets/files/ode-notes.md" download="常微分方程学习笔记.md">下载 Markdown</a>
  …
  <article class="prose fss-qa-article reveal" data-fss-qa data-md="../assets/files/ode-notes.md"></article>
  …
  <script defer src="../assets/vendor/katex/katex.min.js"></script>
  <script defer src="../assets/vendor/katex/contrib/auto-render.min.js"></script>

关键点：底部必须引入 KaTeX 两个脚本（带公式时），否则 $…$ 只显示原文。

第 3 步：建专区落地页

复制 course-engtrain.html，改 <h1> 课程名、hero 文案、1 份资料 计数，以及 .fss-grid 里的卡片：

<a class="fss-file-card fss-file-card-link" href="course/ode-notes.html">
  <span class="fss-file-icon type-md">…</span>
  <span class="fss-badge open">可阅读</span>
  <h3 class="fss-file-name">常微分方程学习笔记</h3>
  <p class="fss-file-meta">Markdown · 约 22 KB · 可在线阅读</p>
  <p class="fss-file-desc">覆盖初等积分法、高阶方程……独立页面渲染全文。</p>
</a>

第 4 步：登记元数据 + 同步统计

在 assets/js/posts-data.js 的数组里加一条（slug 与阅读页文件名对应）：

{
  slug: "ode-notes",
  href: "course/ode-notes.html",
  title: "常微分方程学习笔记",
  cat: "笔记",
  date: "2026-08-25",
  readTime: "约 22 KB",
  cover: "assets/img/cover-notes.svg",
  excerpt: "常微分方程完整学习笔记……",
  tags: ["常微分方程", "课程笔记"],
}

然后跑统计脚本，让「关于我」和右侧标签面板同步：

node scripts/update-stats.js
一句话 checklist 放 assets/files/*.md → 建 course/<名>-notes.html（带 KaTeX）→ 建 course-<名>.html 专区 → 登记 posts-data.js → node scripts/update-stats.js → 本地预览 → git push。
